# 反馈沉淀工作流

本流程用于从真实文档、截图、用户反馈和已核验的上游参考内容中学习并更新 `Doc_Rule`。

开始规则库迭代时先读取 `catalog/upstream-sources.yaml`，按 `workflows/refresh-upstream-sources.md` 检查来源更新，同一任务内不重复检查。上游材料与真实反馈分别标明来源，采用相同的语义去重流程。

## 目标

把“某个具体文档的问题”转化为“可跨项目复用的规则”，同时避免规则库重复膨胀。

候选问题不能只来自已有规则命中，也应来自高阶质量判断发现的新问题。

## 执行步骤

### 1. 先做高阶判断

读取：

- `catalog/evaluation-criteria.yaml`
- 必要时读取 `principles/formal-deliverable-quality.md`

先判断整份文档是否存在：

- 文档身份混杂；
- 解决方案叙事被边界管理压过；
- 作者存在感过强；
- 旧稿迁移或拼接痕迹；
- 自创术语和框架包装过度；
- 信息重复堆叠；
- 工程表达过度文字化或过度包装化；
- 视觉设计喧宾夺主；
- 正式基线不明确。

### 2. 提取候选问题

再对输入材料逐项识别：

- 版式与文控问题；
- 项目名称与主体称谓问题；
- 语态与措辞问题；
- 编号与表格问题；
- 图表与资料来源问题；
- 责任边界与免责式表达问题；
- 高阶评判发现的结构级、叙事级和成品感问题；
- 其他会导致正式文件显得像草稿、内部稿、AI 稿、咨询稿或拼接稿的问题；
- 事实缺乏依据、改写含义变化、数值口径冲突；
- 操作步骤不完整、结果难以判断和受保护技术内容损坏。

每个候选问题先形成一句**抽象的问题定义**，不要一开始就按原句创建规则。

### 3. 去标识化

进入规则库前应去除：

- 真实客户名称；
- 未公开项目编号；
- 敏感日期、设备编号；
- 内部人员信息；
- 其他不适合进入公开规则库的内容。

保留“错误模式”，不保留不必要的业务秘密。

### 4. 搜索现有规则

先读取 `catalog/rules.yaml`，使用：

- title；
- detection_hints；
- dedup_signature；
- applies_to；
- category；

筛选最相近候选规则，再读取这些规则全文。

### 5. 做语义去重

对每个候选问题判断：

- **DUPLICATE**：已有规则已完整覆盖；
- **EXTENSION**：已有规则可覆盖，但值得增加新示例/检测线索；
- **NEW**：具有独立问题机制，需要新规则；
- **CONFLICT**：与现有规则冲突，需要人工确认。

判断依据是“问题机制 + 风险 + 修正原则”，不是表面关键词。

高阶标准中的 Q-xx 不是自动等同于一条具体规则。  
只有当真实反例或经核对的上游案例能够说明稳定、可复用、可检测的问题模式时，才应沉淀为新规则。教学示例须明确标注并给出完整输入依据，不冒充实际项目反馈。

### 6. 处理结果

上游候选内容先列出条款、依据、影响及采用边界；在用户授权范围内执行。用户已批准的条款直接落实，不重复请求确认。新增范围沿用先提案后采用的方式。

#### DUPLICATE

不新增，不修改。

#### EXTENSION

更新已有规则：
- 补充新反例；
- 补充推荐表达；
- 补充 detection hints；
- 必要时补充 applies_to 或例外。

同时更新 `catalog/rules.yaml`（若索引字段发生变化）。

#### NEW

按 `rules/_template.md` 创建新规则，并同步更新：
- `catalog/rules.yaml`；
- 必要时 taxonomy / schema；
- README 仅在结构发生变化时更新。

#### CONFLICT

不自动覆盖。记录冲突点并要求人工确认。

### 7. 最终核对

提交前检查：

- 是否出现同义规则；
- ID 是否唯一；
- catalog 路径是否正确；
- 示例是否去标识化；
- 规则是否同时适合“写作预防”和“完稿审查”；
- 是否至少有 2 个反例和 2 个推荐处理方式；
- 反例与改写是否共享完整输入，事实、否定、条件和范围是否保真；
- 是否有应保留案例和可核验的来源版本；
- 是否只是把某个 Q-xx 高阶标准机械拆成新规则，而缺乏稳定反例；
- 文档类型配置、上游来源引用与规则索引是否一致。

## 推荐输出

反馈沉淀完成后，向用户说明：

- 新增了哪些规则；
- 哪些问题判定为重复而未新增；
- 哪些仅扩展了已有规则；
- 哪些高阶问题暂时只保留为评判标准、尚未规则化；
- 是否存在需要人工决策的冲突。

不需要把全部内部去重思考过程逐字展开。
