# 规则编写规范

本目录按“规则族 / 单条规则”组织。每条规则是一个可独立引用的审查单元。

## 单条规则模板

```markdown
# DR-XXX-000 规则标题

- 状态：active
- 严重度：high / medium / low
- 适用：技术方案 / 标书 / 合同 / …
- 规则类型：版式 / 文控 / 术语 / 语态 / 编号 / 责任表达 / …

## 标准问题描述
用正式、可复用的语言描述问题，不绑定某个具体项目。

## 为什么是问题
说明其对正式性、可读性、责任边界、客户感受或合同风险的影响。

## 判定标准
给出可以执行的判断条件。

## 反例
至少 2 个。

## 推荐表达 / 处理
至少 2 个。

## 检查方法
说明人工或 AI 如何检查。

## 例外
说明在哪些场景下允许存在。
```

## 编写要求

1. 规则描述必须可复用，不依赖单个项目背景。
2. 反例可以来自真实文档，但进入仓库前应尽量去标识化。
3. “反例”用于识别模式，不代表所有包含某个词的句子都错误。
4. 推荐表达应优先给出**直接可替换文本**。
5. 对合同、招标、法规、安全等必须明确边界的场景，应保留必要的否定式约束，不做绝对化禁用。
6. 每条规则应在 `catalog/rules.yaml` 登记，供 AI 和工具快速索引。
