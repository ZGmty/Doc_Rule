# DR-FRM-001 禁止内部提示型版式残留

- 状态：active
- 严重度：high
- 适用：技术方案、标书、合同技术附件、实施方案、验收文件
- 规则类型：版式 / 正式性

## 标准问题描述

**对外正式文件中存在内部编辑提示、备注或强调型视觉样式残留。** 正式技术文件正文应采用统一、克制、稳定的版式体系，不应保留仅服务于编制、审阅、提醒或内部沟通的高亮底色、Callout、提示色块、审阅边线等视觉元素。

## 为什么是问题

这类样式会让最终文件呈现出“尚在编辑”“需要复核”“内部提醒”的状态，削弱正式交付文件的完成度与权威性。即使文字本身正确，版式也会暴露文档仍处于编制过程。

## 判定标准

满足以下任一条件时应重点审查：

- 正文段落使用与全文体系不一致的浅色底纹或高亮背景；
- 出现明显的 Callout、提示框、批注式边线；
- 某段仅因“提醒编制人员注意”而被单独着色；
- 保留修订痕迹、批注、编辑符号或内部说明框；
- 色块既不是正式信息架构的一部分，也没有统一的图例或版式规范。

## 反例

**反例 1**

> [浅蓝底色提示框] 本方案依据现有项目材料编制，最终参数后续确认。

**反例 2**

> [黄色高亮] 注意：此处参数需项目经理二次确认。

**反例 3**

在正式正文中保留 Word 的“Callout / 强调提示”段落样式，仅为了提醒内部人员注意某项风险。

## 推荐处理

**方式 1：直接纳入正式正文**

> 项目参数以双方确认的详细设计成果为准。

**方式 2：纳入正式章节**

将必要内容放入“设计依据”“实施条件”“技术边界”等正式章节，用统一正文样式呈现。

**方式 3：删除纯内部提醒**

若内容只服务于编制人员，例如“此处待补图”“需项目经理确认”，正式交付前必须删除。

## 检查方法

AI 或自动化工具除检查文字外，还应检查：

- paragraph shading / run highlight；
- text box / callout；
- comments / tracked changes；
- 异常边框与强调色；
- 与正文样式集不一致的局部格式。

## 例外

正式文件本身已有统一设计规范时，允许使用规范化的信息框，例如“重要提示”“安全警告”，但必须有明确语义、统一样式，并面向最终读者，而不是面向内部编制人员。
